Providers and 1,042 models

Run pi --list-models and over a thousand entries scroll past, each with a context window, a price list, and capability flags. Where does that knowledge live? In the largest — and least interesting to read — part of pi-ai: generated data. This lesson is about models as metadata, and the small runtime that serves it.

A model is a record

Everything pi needs to know to use a model responsibly: which wire protocol it speaks (api), where (baseUrl), whether it can reason and see images, how big the conversation may grow (contextWindow), and — crucially — the four-way price list. The file this lives in is stamped "auto-generated" at the top: a script (scripts/generate-models.ts) compiles these catalogs from upstream sources. There are ~18,700 lines of entries like this across 35 provider catalogs — 258 for OpenRouter alone.

Engineering · Generated code: data wearing a code costume

Why generate TypeScript instead of shipping a JSON file? Because code gets type-checked: every entry is validated against Model<"anthropic-messages"> at compile time (that's what satisfies does — "check this literal against that type, but keep its precise inferred type"). A typo'd field in 18,700 lines fails the build instead of failing a customer.

The rules for generated code: never edit it by hand (pi's AGENTS.md makes this an explicit law — fix the generator instead), don't review its diffs line by line, and don't count it when judging a codebase's size. "36,000 lines of pi-ai" sounds intimidating; it's really ~17k of prose-worthy code plus a big, machine-written phone book. Learning to spot which is which — check for a generator header, check the repetition — instantly shrinks any large repo you open.

A provider is a binding

Models are grouped by provider — the vendor you have an account with. In code, a provider is a tiny factory that binds together a catalog, authentication, and a wire-protocol implementation. Here is the entire Anthropic provider:

Twenty lines, four decisions: who (id, baseUrl), how to log in (an environment-variable API key, or an OAuth flow for Claude subscription accounts), what's on the menu (the generated catalog), and which dialect to speak (the anthropic-messages adapter — next module's subject). Most of the 35 provider files look just like this; many are shorter, because they reuse the OpenAI-compatible adapter and differ only in URL and models.

The runtime: cost accounting

The metadata isn't decorative. Every response's token counts are priced through one function:

LLM · What tokens cost, and why four prices

Models bill per million tokens (a token ≈ ¾ of an English word), with separate rates for input (everything you send — remember, the whole conversation, every turn) and output (what the model generates), output typically 5× dearer. The two cache rates belong to prompt caching (lesson 4.6): providers will remember a prefix of your prompt for a few minutes, then charge ~10% of the input rate to re-read it — a 90% discount on an agent's biggest expense, since each loop turn resends a growing transcript. Writing the cache costs a small premium, and Anthropic's 1-hour retention tier costs more still — hence the special case in the code, and the cacheWrite1h field you may have wondered about in Usage. Pricing quirks ripple all the way into type definitions.

The collection: Models

One object ties it together: a Models collection built from all registered providers, with lookups like getModel("anthropic", "claude-sonnet-4-5"), dynamic refresh for aggregators whose catalogs change daily (refreshModels() — note the in-flight deduplication in createProvider, so concurrent refreshes don't stampede), and auth resolution. The coding agent wraps this in its own ModelRegistry with settings and custom entries; extensions can register whole new providers (Module 8). Every layer asks this collection one question: given a provider and an id, give me the metadata and a function to stream with.

What you now know

Models are typed records in generated catalogs; providers are 20-line bindings of catalog + auth + adapter; and cost is computed, not guessed, from per-model price tables. Next: the event grammar — the full discriminated union that every streaming response in pi is narrated in.
