The compatibility nightmare

Twenty vendors claim to speak "the OpenAI API." None of them speak quite the same one. This lesson is the most honest in the course: it shows what engineering against the real world's marketing claims looks like — and the pattern pi uses to keep the mess governable.

The dream and the reality

The dream: since Groq, DeepSeek, Together, xAI, Cerebras, OpenRouter and friends all imitate OpenAI's chat-completions API, one adapter should serve them all. The reality, discovered one bug report at a time: this one rejects max_completion_tokens and wants the deprecated max_tokens; that one doesn't know the developer role; a third crashes on the store field; and ten of them invented mutually incompatible ways to switch on reasoning.

Engineering · Compatibility profiles and feature detection

This mess has a proud lineage: web browsers. Decades of "every browser claims to support the standard, differently" produced the same three-part answer you see here: a capability checklist instead of if-else chains scattered through logic (if (compat.supportsStore) reads and audits far better than if (provider !== "nvidia" && provider !== "together" && ...) repeated forty places); centralized detection so knowledge about vendors lives in exactly one function; and user-suppliable overrides as the escape hatch.

The meta-lesson: when you must depend on many implementations of one "standard," don't model vendors — model capabilities. Vendors multiply; capabilities converge to a few dozen booleans. (pi even defines a second, smaller profile for Anthropic-compatible resellers — the pattern recurs wherever a standard gets popular.)

Where the flags bite

Scattered through the adapter's request builder, each flag has its moment: the messages array uses role developer or system; thinking blocks get serialized as structured fields or wrapped in <thinking> text delimiters; the reasoning knob is spelled per thinkingFormat; tool schemas gain or lose strict. The logic stays linear; the flags absorb the branching. And when a vendor fixes or breaks something — the git log shows this weekly — the diff is one line in detectCompat plus a regression test.

Note · why this lesson matters beyond pi

Most tutorials show you the Anthropic adapter's world: one vendor, clean spec. Most careers are spent in this lesson's world: payment processors, SSO providers, cloud APIs, browser quirks. The compat-profile pattern — checklist, detection, override — transfers to all of them. This unglamorous file may be the most professionally useful one in the course.
