OAuth and the faux provider

Two loose ends close out the pi-ai layer: how /login actually works when you have a Claude or Copilot subscription instead of an API key, and the scripted fake model that lets 250+ tests exercise the whole stack for zero dollars. Both are skims by design — concepts, not line-by-line.

Part 1: logging in without an API key

API keys are simple: an environment variable, a header, done — that's the envApiKeyAuth line you read in the Anthropic provider (lesson 3.3). But subscriptions (Claude Pro/Max, GitHub Copilot, ChatGPT plans) don't hand out long-lived keys. They use OAuth: you prove your identity in a browser; the app receives tokens. pi ships full flows for Anthropic, GitHub Copilot, and OpenAI Codex — about 2,000 lines under packages/ai/src/utils/oauth/.

Three engineering points worth keeping, even at flyover altitude:

  • Tokens expire; design for mid-session refresh. Access tokens last minutes-to-hours. Now the odd detail from lesson 2.4 pays off: the agent loop resolves the API key fresh on every model call precisely because "the key" may need to be a just-refreshed token.
  • Refresh must be serialized. If parallel requests both notice an expired token, both might refresh — and some providers invalidate the older token, logging you out at random. pi's credential store wraps updates in a serialized read-modify-write (CredentialStore.modify()) so exactly one refresh wins. Classic concurrency bug, solved where the data lives.
  • Auth is data, not code. A provider's auth block just declares ways to get a credential (env key, OAuth flow); resolution happens in one place (src/auth/resolve.ts). That's why extensions can add whole new login flows (Module 8) — they're just supplying another record.

And the stealth-mode digression from lesson 4.2 completes the picture: OAuth sessions get Claude-Code-style tool names because the subscription endpoint expects Anthropic's own client. Auth mode even changes the request payload — one more thing adapters absorb.

Part 2: the faux provider

Question from lesson 1.5: how do 294 test files test an AI agent without paying for models? Answer: faux — a 538-line provider whose "model" is a script you write in your test:

A test scripts a conversation like a playwright:

The faux provider implements the same two-function ProviderStreams interface as every real adapter — it even streams, chopping its scripted text into deltas of 3–5 characters so consumers experience realistic event sequences. Everything above the interface line — loop, tools, session persistence, compaction, extensions — runs completely real, deterministic, offline, free. The repo's own rules mandate it: agent tests use the faux provider, "no real provider APIs, keys, or paid tokens."

Engineering · Test doubles at the network boundary

A fake is a working implementation taking a shortcut (faux: scripted answers instead of a neural network) — distinct from a mock, which just records calls. Fakes shine when placed at a natural seam, and the best seam is almost always the network boundary: substitute the expensive/nondeterministic remote thing, keep 100% of your own code under test.

The transferable rule: the quality of your abstractions determines the quality of your tests. Because pi routed all providers through one small interface, a fake provider slots in with zero special-casing — the agent genuinely cannot tell. If your code is hard to test, the fix is usually not better mocks; it's a boundary like this one. (Python: an httpx MockTransport, or a fake implementing your repository protocol.)
