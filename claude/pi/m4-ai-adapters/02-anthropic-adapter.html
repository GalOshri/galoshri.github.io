Deep dive: the Anthropic adapter

Leg 1: building the request

The outbound half is translation-by-walking: convert each normalized message into Anthropic's JSON dialect (their tool results live inside user messages; thinking blocks need their signatures reattached; images become base64 source objects), serialize the TypeBox schemas into the tools array, map the thinking level to a token budget, and POST it to /v1/messages with stream: true. Leg 2: bytes to lines to events

The response arrives as an HTTP body that stays open for the whole generation, dribbling Server-Sent Events. Raw, it looks like this:

Web · Server-Sent Events (SSE)

SSE is the simplest streaming protocol imaginable: one long HTTP response whose body is text, divided into frames by blank lines; each frame has event: and data: lines. No binary framing, no handshake, no library required — curl can speak it. That simplicity is why every LLM provider chose it over WebSockets for response streaming (pi supports WebSocket transports for a couple of providers, but SSE is the lingua franca).

The one genuine subtlety: the network doesn't respect your framing. A TCP read may deliver half a frame, or three and a half. Any SSE parser is therefore a buffering loop: append bytes, extract complete lines, keep the remainder. Watch for exactly that shape below.

There's the buffering loop, as an async function* — JavaScript's yield-based generator, made asynchronous (you met the consuming side in lesson 2.4; this is the producing side). reader.read() gives raw bytes; the TextDecoder with {stream: true} even handles a multi-byte UTF-8 character split across network chunks. Complete lines are peeled off one at a time; partial ones wait in buffer for the next chunk. Every streaming parser you will ever write has this exact skeleton.

Second stage of the pipeline: filter to known event names, JSON-parse each frame (with the repair parser — even provider JSON isn't fully trusted), and track whether the stream properly started and ended. That bookkeeping matters: a connection that dies mid-generation produces "stream ended before message_stop" — an error you'll meet again in the retry lesson.

What you now know

An adapter is three pipelined loops: build-and-send, bytes-to-frames, frames-to-grammar — with the partial message maintained in the middle and every quirk of one vendor quarantined inside one file. Now brace yourself: next lesson is the adapter that has to please twenty vendors at once.
