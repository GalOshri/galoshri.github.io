Tools: read, ls, grep, find

The observation tools — the model's eyes. Their schemas are trivial; their engineering is entirely about one scarce resource. A file is megabytes; the model's attention is a fixed number of tokens; every tool that produces output must therefore budget output.

LLM · The context window as a scarce resource

A model reads at most its context window — for Claude Sonnet, 200k tokens, maybe 150k words — and that budget holds everything: system prompt, conversation, every tool result ever returned this session. Worse, the budget is shared over time: a wasteful tool result doesn't just crowd this turn, it gets re-sent (and re-billed, lesson 4.6) on every future turn until compaction reaps it.

So agent tools obey an economy of attention: return the least output that answers the question, tell the model what was withheld, and give it knobs to ask for more. Watch all three principles appear in code below. When people say "context engineering" is the real craft of agents, this — plus system prompts and compaction — is what they mean.

The budget, made concrete

One shared module, used by every tool. Two limits because they fail differently: 2,000 short lines is fine reading, but 2,000 lines of minified JavaScript would be a token bomb — the byte cap catches it. "Never returns partial lines" matters more than it looks: a line cut mid-token confuses models into hallucinating the rest. And grep gets a per-line cap too — one match inside a bundle file could otherwise be 200KB of line.

The TruncationResult type carries rich metadata — truncated, truncatedBy, totalLines, outputLines — because the cut must be narrated: the model sees a note like "output truncated at 2000 of 8,344 lines; use offset/limit to read more." An unexplained cut looks like the file simply ends; an explained one is an invitation to page.

read: paging, images, and pluggable I/O

ls, grep, find: the supporting cast

Each is a few hundred lines of the same recipe — schema, operations interface, truncation, a renderer for the TUI. Their specific virtues: ls annotates directories and sizes; grep wraps a regex search with match-context lines, the 500-char line cap, and result counts; find does glob matching with .gitignore awareness — because node_modules would otherwise dominate every result list, burning tokens on noise the model never wants. Even ignore-files are context engineering.

Remember these three are inactive by default (lesson 6.2) — bash covers them when present. Their careful existence is for the locked-down configurations where bash is exactly what you've removed.

What you now know

Observation tools are budget enforcement wearing a schema: two-limit truncation, narrated cuts, paging knobs, and pluggable I/O. Next: the tool with the opposite problem — bash doesn't read the world, it changes it, while its output streams live and its processes need killing.
