createAgentSession: wiring it all together

One function in core/sdk.ts assembles the product: it builds an Agent from Module 5, plugs every hook with product behavior, and wraps the result in AgentSession. Reading it is like seeing the whole course's wiring diagram executed.

Defaults with opinions

Seven tools exist (read, bash, edit, write, grep, find, ls) but only four are active by default. Why exclude the search tools? Because bash already covers them — the model can run grep and find as commands — and every tool definition costs context tokens and decision complexity. The dedicated grep/find/ls tools exist for restricted setups (a read-only reviewer agent with no bash). Tool selection is prompt engineering.

Read it hook by hook, as a reunion:

  • streamFn — the loop's "how do I talk to a model" function (lesson 2.4), now doing product work: resolve auth fresh per call (OAuth tokens expire, lesson 4.7), apply the user's retry and timeout settings, merge attribution headers. Note the battle-scar comment about timeout=0 — the kind of knowledge only production teaches.
  • convertToLlm — the boundary from lesson 5.1, wrapped with a "block images" filter: if the user disables image reading, images are stripped at the conversion point, even if a tool smuggled one into the transcript. The narrowest point is where you enforce policy — that's called defense in depth.
  • onPayload / transformContext — both forward straight to the extension runner. Extensions literally are loop hooks with a registration system (Module 8's whole secret, revealed early).

AgentSession: the product wrapper

The configured Agent then disappears inside AgentSession (core/agent-session.ts, 3,175 lines — next lesson's subject in a different way). The session subscribes to the Agent's broadcast and does product things with each event: append messages to the JSONL file, refresh the cost totals, trigger auto-compaction between turns, fan events out to extensions and to whichever mode is running. It also owns the retry policy — lesson 4.4's classifier finally meets its policy here — plus prompt()/abort()/fork() and every operation slash commands need.

Note · this function is also the public SDK

createAgentSession() is exported: any Node program can import { createAgentSession } from "@earendil-works/pi-coding-agent" and embed the full coding agent — tools, sessions, extensions — headlessly. The same wiring that boots the CLI is the library's front door. Products that are also SDKs keep themselves honest; there's no hidden magic only the CLI can do.
