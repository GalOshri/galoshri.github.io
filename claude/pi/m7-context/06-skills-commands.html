Skills, templates, slash commands

Three features that sound distinct — skills, prompt templates, slash commands — and turn out to be variations on a single move: getting the right text into the context at the right moment. Seeing through them completes your model of how agents are actually steered.

Skills: knowledge the model fetches itself

A skill is a directory containing a SKILL.md — markdown with a small frontmatter header (name, description) followed by instructions: how to release this project, how to write a migration, how to review a PR. Discovered from .pi/skills/ and the global dir, they get advertised in the system prompt — but only as a catalog: name and one-line description each. The full text stays on disk until the model decides a skill is relevant and reads it — with the tool from lesson 6.4, budgets and all.

That's the entire trick, and it's the context economy again: a fat skill library costs a few lines per skill per request, not kilobytes. Advertise cheaply, load lazily — the same shape as lazyApi (3.6) and dynamic imports, applied to knowledge. (pi's repo has a skill of its own: .pi/skills/add-llm-provider.md teaches the agent how to add a provider to packages/ai — institutional memory as loadable text.)

Prompt templates: parameterized messages

A prompt template is a markdown file in .pi/prompts/ whose body contains placeholders — $1, $2, $ARGUMENTS. Typing /review-pr 4187 expands the template with your arguments and sends the result as your user message. No model involvement in the expansion — pure string substitution, like a shell alias for prompts. Where a skill is knowledge the model pulls, a template is phrasing you push.

Slash commands: the umbrella

You met the dispatcher in lesson 2.1 — the onSubmit chain. The full picture: a command's source is one of three kinds, and the type in the code says so directly — SlashCommandSource = "extension" | "prompt" | "skill", layered over ~40 built-ins:

KindExamplesWhat typing it does
built-in/model, /compact, /fork, /resume, /loginruns app code — never reaches the model
prompt template/review-pr 4187expands text → sends as your message
skill/add-llm-providerinjects a skill invocation → model reads the skill
extensionanything a plugin registersruns the extension's handler (Module 8)

One prefix, one autocomplete list, four escalating levels of machinery behind it. Users never need to know which kind they're invoking — a good CLI hides its own taxonomy.

The unifying picture

Different lifetimes, different payers, different triggers — but every mechanism in this module manipulates the same thing: the token stream the model reads. Once you see agents this way, new features become predictable. "Memory"? Text injected from a store. "RAG"? Text retrieved into context. "Personas"? System-prompt text. The implementation patterns you've read — discovery walks, lazy loading, frontmatter catalogs, budget-aware truncation — are the whole toolkit, recombined.
