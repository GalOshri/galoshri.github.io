Project context: AGENTS.md

In lesson 1.5 you read pi's own AGENTS.md as a constitution. Now the mechanism: how a markdown file in your repo becomes standing orders in the model's head — the closing of the loop where a codebase instructs the agents that work on it.

The discovery walk

Three design choices in thirty lines:

  • The candidate list is diplomacy. AGENTS.md is the emerging cross-tool convention; CLAUDE.md is Claude Code's older house name. pi reads both, first match per directory — your repo shouldn't need one rules file per AI vendor.
  • The walk goes all the way up. Run pi in ~/work/monorepo/packages/api/ and it collects context from packages/api/, the monorepo root, and anything between — plus your global file. Nested rules for nested scopes, exactly like .gitignore layering.
  • unshift sets the precedence story. Files are assembled outermost-first: global rules, then repo-wide, then most-specific-directory last — and in prompt-land, later text tends to win when instructions conflict. The most local authority speaks last.

The path attribute means the model can even tell a user which file imposed a rule.

What goes in one (and what shouldn't)

Having read pi's own AGENTS.md, you know the genre: build commands, style rules, "never do X" tripwires, test invocations, commit etiquette. The economics from lesson 6.4 apply — every line rides in every request, forever. So the craft is ruthless brevity: what must the agent always know, versus what it can read on demand? (pi's own file points at deeper docs rather than inlining them — and the skills system next lesson is the formalization of "on demand.")

Note · the loop, closed

Savor the recursion you can now fully explain: pi's repo contains an AGENTS.md → pi (run in that repo) injects it into its own system prompt → the model edits pi's source under those rules → including, sometimes, editing AGENTS.md itself. A codebase that documents itself to the agents that maintain it, using the mechanism it implements. Every layer of that sentence is code you've read.
