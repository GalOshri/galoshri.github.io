The model asks to read a file

LLM · Tool calling

How does a text generator emit structured requests? By agreement. With each API call, the client sends tool definitions: name, human-readable description, and a JSON Schema of the parameters. The model was trained to respond, when appropriate, with a special kind of output that providers parse and return as a distinct content block — not prose. The client executes whatever the call describes and sends back a tool result message; the model reads it and continues.

Two things to keep straight. First, the model never executes anything — it only ever produces the request; all power stays in the client, which is why pi (not the model) is the security boundary. Second, the model can and does get it wrong: misspelled tool names, arguments that violate the schema, JSON cut off mid-string. Real systems validate every call — pi does, with the same schema objects, before anything runs.

One definition, three jobs. Lesson 3.2 dwells on this trick, which the entire tool system rests on.

The tool also has an execute function. For read it does roughly what you'd guess — resolve the path, read the file — plus the unglamorous production concerns that make up most of its 350 lines: cap output at a line/byte budget so a huge file can't flood the conversation, detect images and attach them properly, prefix line numbers. Around the loop once more

The conversation now reads: user question → assistant "I'll look" + tool call → tool result with the file's contents. The inner loop turns, ships the whole thing to the model again, and this time the model has everything it needs. Its second reply is pure prose — "This package.json defines your project's metadata, dependencies, and the scripts you can run with npm run…" — with stopReason: "stop". No tool calls; the loop ends.

What you now know

Tool calling is a three-message dance — request block, execution, result message — governed by schemas the client declares and validates. The model supplies intent; pi supplies capability and safety. Our traced answer now exists in memory. Two lessons remain: how it reached your eyes, and how it reached your disk.
