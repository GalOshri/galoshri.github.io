AgentHarness: sessions, trees, compaction

Above Agent, the library ships one more layer: AgentHarness, a "batteries included" runtime with persistence, branching, compaction, and skills built in. We tour it at medium altitude — partly for its own ideas, partly to set up next lesson's twist.

What the harness adds

An Agent forgets everything when the process exits, and every app needs the same next five features. The harness (~1,000 lines in packages/agent/src/harness/) packages them:

The session tree

The harness persists a conversation not as a list but as an append-only tree of typed entries — the design you previewed in the session file (lesson 2.7). The entry vocabulary, from the harness types:

Notice what became entries: changing the model isn't a settings mutation, it's a fact in the log — so replaying the log reproduces not just what was said but under which configuration. Every entry has id/parentId; the leaf pointer names the active branch. Rewind-and-retry appends a new child to an old entry and moves the leaf. Nothing is ever deleted.

Compaction, previewed

The harness also owns the answer to "the conversation outgrew the context window": pick a cut point that keeps recent turns intact, ask a model to summarize everything before it, and append a compaction entry holding the summary. Future context = summary + everything after the cut. The tree keeps the full history — compaction changes what the model sees, never what the file remembers. The coding agent's version of this gets a full lesson (7.3), with the actual budgets and cut-point algorithm.

ExecutionEnv: the quiet abstraction

Subtlest piece: harness code never touches fs or spawns processes directly. It goes through an ExecutionEnv — an interface bundling a FileSystem and a Shell, with a Node implementation provided. Swap the env and your agent's tools run against SSH, a container, a sandbox — without the agent noticing. Remember the read tool's pluggable ReadOperations (lesson 2.5)? Same move, one level up. Boundary-drawing for testability and deployability: the faux provider faked the model; ExecutionEnv can fake (or relocate) the world.

Note · the hook map

The harness also defines a large typed event/hook map — before_agent_start, before_provider_request, tool_call, session_compact, and ~20 more, each with typed results that can mutate behavior. Hold the thought: the coding agent's extension API (Module 8) is this same design, grown independently. Seeing the pattern twice is next lesson's point.

What you now know

The harness turns the Agent into an application platform: an event-sourced session tree, compaction, typed hooks, skills, and a pluggable world. A reasonable person would now assume pi's coding agent is built on it. It isn't — and the reasons why are one of the most instructive stories in the repository. Next lesson: the plot twist.
