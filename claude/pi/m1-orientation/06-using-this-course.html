How to use this course

A four-minute orientation to the course's own machinery: what the colored boxes mean, how deep each module goes, and what to do when something doesn't stick.

Everything you need is on the page

Every lesson is self-contained. Real code appears as excerpts with a header bar naming the file it came from — like packages/agent/src/agent-loop.ts — so you always know the provenance, but you never need to open that file. Diagrams, example messages, wire payloads: all embedded. The header paths become useful the day you want to explore the source yourself (a copy lives at ~/Projects/pi), and not before.

The colored boxes

New concepts arrive exactly when the code first needs them, in one of four flavors — each explained from a Python programmer's point of view, and each introduced only once:

TypeScript · language features

Blue boxes decode TypeScript: unions, generics, narrowing, and other things Python's type hints only gesture at.

Node.js · runtime & ecosystem

Green boxes cover the Node platform: modules, event emitters, child processes, promises — the asyncio-shaped parts.

LLM · how models are driven

Violet boxes explain the AI side: messages, tool calling, streaming, context windows, caching. No machine-learning math — this is the engineering interface to a model.

Engineering · timeless craft

Amber boxes are language-agnostic engineering: layering, append-only logs, adapters, test doubles. These transfer to every codebase you'll ever read.

Other furniture

  • Walkthroughs — code broken into short segments with commentary between them, marked by a colored rail on the left. Read them top to bottom; the segments are one continuous piece of code.
  • Digressions — collapsed "＋" sections. Optional depth; skip freely, nothing later depends on them.
  • "Go deeper" callouts — gray boxes at the end of some lessons pointing at source files or official docs. Also entirely optional.
  • Elisions — excerpts trim irrelevant lines and mark the cut with // .... Anything unmarked is verbatim from the repository.

The shape of the journey

Module 2 is the keystone — it follows one message from your keyboard through every layer and back to your screen, at low resolution. Read it even if you read nothing else; every later module answers questions Module 2 plants. After that, the course descends the dependency stack: the LLM interface (3–4), the loop (5), the product (6–8), the terminal machinery (9), and a short appendix (10). Modules after 2 are largely independent of each other — if extensions excite you more than wire protocols, jumping from 5 to 8 is legal.

Advice, briefly

  • Read code slowly, once. One careful pass over an excerpt beats three skims. If a line resists, the surrounding prose almost certainly addresses it.
  • Don't memorize. The goal is recognizing shapes — "ah, a discriminated union", "ah, an adapter" — not recalling names. Shapes recur; names don't.
  • Two lessons a sitting is a good sustainable pace. The minutes-per-lesson figures in the sidebar are honest.
  • Expect drift. pi moves fast; if you ever compare against the live repo and a line number is off, trust the concepts, not the coordinates.

That's the whole manual. On to the main event: one message, all the way through the machine.
