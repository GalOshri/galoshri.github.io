Reading three real extensions

The repo ships ~60 example extensions — from permission gates to a playable DOOM overlay. We read two closely and survey the zoo, because each example is a different answer to "which hook, used how?"

1. permission-gate: the guard pattern

Thirty lines, and it's a permission system. Trace the mechanics with what you know: the tool_call event is the runner's fan-out of beforeToolCall (5.3); returning { block: true, reason } becomes an error tool result the model reads — so the model learns "Blocked by user" and adapts, rather than crashing. Three details are professional-grade: return undefined means "no opinion" (other extensions still get their say); ctx.hasUI handles headless modes — fail closed when nobody can approve; and the handler being async means it can park the entire agent loop on a human decision — the awaited-listener guarantee (5.4) making an interactive veto possible at all.

2. git-checkpoint: the state-sync pattern

This one fixes a real conceptual gap you can now articulate precisely: Module 7's session tree time-travels the conversation, but not your files — rewind three turns and the code still has all three turns' edits. The extension pairs the two histories: at each turn_start it snapshots the working tree (git stash create makes a commit without touching anything), keyed by session-entry id; on fork, it offers to restore the matching snapshot. Conversation tree ↔ code tree, stitched by forty lines and two hooks. This is the pattern for syncing any external state — databases, running services, browser tabs — to the agent's timeline.

3. The zoo, as a map of the hook space

  • Guards: confirm-destructive, protected-paths, dirty-repo-guard — variations on tool_call veto.
  • Workflow: plan-mode (a read-only planning phase — setActiveTools in action), auto-commit-on-exit, handoff.
  • Context surgery: custom-compaction (replace Module 7's algorithm!), input-transform, dynamic-resources.
  • Infrastructure swaps: custom-provider-anthropic (next lesson), bash-spawn-hook, sandbox/gondolin (route tools into a VM — the BashOperations seam from 6.5).
  • UI play: custom-footer, message-renderer, snake, doom-overlay — proof the TUI layer (Module 9) is fully exposed too.

Pedagogically, this directory is pi's real extension documentation — and the system prompt points the model at it (7.4), so examples double as the corpus pi consults when you ask it to extend itself. Documentation, test suite, and training data in one folder.

What you now know

Guard, state-sync, and a taxonomy: most extensions are one well-chosen hook plus a little state, and the ~60 examples cover the hook space like a map. One extension power remains — replacing the model layer itself. That's the finale of the module.
