Extending the model side

The deepest extension power: registerProvider replaces or adds the thing that talks to models. It's also where the whole course closes a circle — because implementing a provider means supplying the exact contract you learned in Module 3.

What registerProvider takes

The API's own doc examples (from core/extensions/types.ts) sketch the three use cases:

Case 1 is the corporate reality (every company has a gateway) solved with pure configuration — the compat machinery from lesson 4.3 does the dialect work. Case 3 is the profound one: that streamSimple signature is the StreamFunction contract from lesson 3.6 — return an AssistantMessageEventStream (the push-queue you built by hand in 3.5), emit the twelve-event grammar (3.4), encode failures as error events, never throw. Supply that one function and everything else in this course — loop, tools, sessions, compaction, TUI — works unchanged on top of your backend. A well-designed interface is a teaching syllabus in disguise; you've effectively already learned how to write a provider.

(The custom-provider-anthropic example proves the point by reimplementing the whole Anthropic adapter — SSE parsing and all — as a standalone extension; the gitlab-duo example targets an API pi never heard of. Registration also hooks the auth system, so a custom provider can ship its own OAuth login for /login — the lesson 4.7 machinery, also pluggable.)

Why the deepest hook matters most

Notice what this does to the dependency diagram from lesson 1.4: user code can now stand below the product, at the pi-ai layer. The extension system doesn't just decorate the agent — it makes every layer's seam public: providers (this lesson), tool I/O (operations/BashOperations, 6.4–6.5), context (transformContext, custom compaction), UI (renderers), commands. The architecture you've studied isn't just clean for maintainers; the cleanliness is the product surface. That's the real meaning of "harness" in "pi agent harness."

Module 8 — and the whole agent story — closed

You now hold the complete picture this course promised: what an agent is (a loop), what it's made of (messages, tools, adapters, state, hooks), how it remembers and forgets, and how it's extended — down to swapping the model itself. It's the most self-contained module — and after the abstractions of the last four, honestly, a joy.
