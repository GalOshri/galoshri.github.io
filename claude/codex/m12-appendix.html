Building, running, and debugging

Everything is driven by just, a task runner. The justfile sets its working directory to codex-rs, so you can run these from anywhere in the repo:

So just c "explain this repo" builds and runs Codex from source. just clippy runs the linter with the rules from Module 1. just fmt formats everything, in four languages, through one Python script.

Rust · The build you should expect

A cold cargo build of 126 crates and 1.2M lines takes a long time and a lot of RAM. Incremental builds after that are fast, because Cargo only rebuilds crates whose dependencies changed — which is the payoff for all that crate-splitting ceremony from Module 1. If you only want to poke at one crate, cargo build -p codex-execpolicy builds it and its dependencies alone.

Some other recipes worth knowing:

just app-server-test-client is the one to reach for if you want to see the protocol from Module 10 with your own eyes: it builds a real binary and drives it as a client, printing the JSON-RPC traffic.

When you need to know what the model saw

After Module 5's context manager, Module 11's assembled AGENTS.md, injected skills, and compaction, reconstructing the actual prompt by reading code is impractical. Use the tools built for it: codex-rs/core/src/prompt_debug.rs and codex-rs/response-debug-context. There is also codex doctor for config and auth problems — it can tell you which config layer won, which is exactly what the provenance design in Module 11 is for.

Careful

Running Codex from source runs a real agent with real credentials against your real filesystem. Start it in a scratch directory, and consider --ask-for-approval untrusted while you are experimenting. The sandbox is good, but Module 8's whole point is that it is the last line, not the first.

Where to go from here

You now have a map of a codebase most people bounce off. Some suggestions, roughly in order of effort.

Read one file completely. Not skim — read. codex-rs/core/src/safety.rs is the best candidate: about 200 lines, no dependencies you haven't met, and it is the security decision at the heart of the product. You have already seen most of it across Modules 2, 3, and 8.

Follow one feature end to end. Pick something small you can see in the UI — the token counter, say. Find TokenCountEvent in protocol, then who emits it in core, then who renders it in tui. Tracing one thread through all three layers teaches more than reading any single crate.

Run it against itself. Codex is developed using Codex. Point it at this repository and ask it to explain a crate you skipped — code-mode, or exec-server. You now know enough to check whether the answer is true, which is the only way that exercise is worth anything.

Write a tool. Module 7 gave you the anatomy: a *_spec.rs declaring the schema, a handler implementing CoreToolRuntime, registration, tests. It is the smallest change that touches the model, the protocol, the sandbox, and the UI at once.

Engineering · What this codebase is actually teaching

The agent loop is about 200 lines. Everything else — 1.2 million lines — is the answer to "what if this has to work for millions of people, on three operating systems, against an untrusted model, without losing their data or wrecking their machine?" If you take one thing from this course, take the ratio. Building an agent is easy. The distance between that and Codex is sandboxing, protocols, persistence, telemetry, extension points, and compatibility — and that distance is the actual job.

A caveat about freshness

This course was written against one commit, named in the footer of every page. openai/codex moves fast: files get split, crates get renamed, WireApi may sprout a second variant. The architecture here should stay recognisable far longer than any individual line number.

When something no longer matches, the techniques still work. Read the Cargo.toml before the source. List public items before reading bodies. Ignore _tests.rs on the first pass. Read the doc comments — in this codebase they are the architecture document, because there isn't one. And trust the enums: in a codebase this disciplined about making illegal states unrepresentable, the type definitions tell you what is true.
